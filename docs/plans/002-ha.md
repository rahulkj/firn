## Phase A — Block engine, single node (delivered 2026-11-13, pending storage review)

Goal: `FileLog` produces **sealed block descriptors** — immutable, content-addressed (`block_id = SHA-256(content)`), carrying absolute offsets and per-frame CRC xor — without any client-visible change. This is the substrate for replication; it is a strict subset of ADR-007 with single-node semantics.

**Delivered:** `internal/log/block.go` (descriptor + `Blocks()`), `internal/log/filelog.go` (rolling digest per segment, `WithBlockSealing` early seal timer, `sealed` marking on roll/recovery, `readFrameAt` now returns raw frames), `internal/log/block_test.go`. No API, no broker, no recovery semantic changes; client-visible behavior is unchanged.

**Tests:** seal bounds on size-roll, early time-triggered seal, deterministic IDs across reopen, content-addressed identity (fixed timestamps), empty-tail exclusion, sealed blocks immutable under later appends. `internal/log` suite + kill-9 fault injection all green with `-race`.

**Storage review gate: mandatory.**

## Phase B — Metadata quorum (control plane) (delivered 2026-11-13, pending storage review)

Goal: 3-voter embedded metadata quorum (ADR-007) — in-house minimal Raft (human decision: in-house, no new dependencies).

**Delivered:** `internal/quorum/` — node core (`quorum.go`: hard state + committed index persisted atomically to `hardstate.json`; CRC-framed append-only `log.bin` mirroring internal/log's recovery discipline), Raft engine (`raft.go`: pre-vote + election, AppendEntries replication with back-off, majority commit (current-term only), no-op on election, randomized election timeouts), `LocalTransport` (in-process; TCP lands with phase C when replication needs the wire). Metadata entries: `noop`, `topic-create`, `block-commit` (block descriptors materialize for phase C).

**Acceptance (all passing, `-race` stable across repeated runs):** 3-node leader election; leader failover to survivors; committed state survives full cluster shutdown/restart (visibility without new election); block descriptor committed and readable on every node; follower proposals rejected.

**Review gate: storage-adjacent (metadata on disk).**

## Phase C — Replication & lease tails (data plane) (delivered 2026-11-13, pending storage review)

Goal: `BlockFetch` replication, lease-granting quorum, epoch fencing at seal/append/ack, unseal→re-seal on failover. Fault injection: kill lease holder mid-seal; fenced-zombie test; 3-node kill -9 restart.

**Delivered:** `internal/replication/` — `ReplicaFetch`/`ReplicaPut` block replication (pull-on-read for hand-over), leader-driven lease maintenance in the agent loop (renewal, expiry, rebalance-to-active-leader on dead holder), epoch fencing in the broker advisor (writes rejected on non-holders), gRPC-based quorum transport riding the same listener as EventingService (one port per node), `ReplicaService` server. Live 3-process SIGKILL test: produce → kill holder → survivors take lease → rejoin → pull catch-up verified.

**Acceptance (all passing, `-race` stable across repeated runs):** single-leader stability; byte-identical replicas; kill holder → survivor takes lease; zombie writes rejected; replicated state survives full cluster restart.

**Review gate: mandatory (storage + failover semantics).**

## Phase D — Client routing (delivered 2026-11-13)

`GetMetadata` RPC (`internal/api/eventing.proto`, `eventingpb` generated) returns per-partition lease holder node id + advertised address. `eventing-cli` routes produce/fetch to the holder with TTL cache (2s) and refresh-on-retry. `eventingd` cluster mode (`-node-id`/`-peers`/`-lease-ttl`) wires: TCP gRPC quorum (same port as client listener), replication agent in the tick loop, `ReplicaService`, write-lease advisor, `ClusterView` for metadata responses. Topics created in cluster mode land on the quorum leader and fan out to followers via the apply hook — `POST /topics` returns 202 propagating.

**Delivered:** TCP quorum + topic-create replication verified live (produce on all three nodes, fetch from any, SIGKILL + restart + pull catch-up).

## Phase F — Internal topics on blocks (delivered 2026-11-13, pending storage review)

`__consumer_offsets`, `__queue_attempts`, `__audit`, `__api_keys` — all four internal single-partition logs are now first-class replicated topics: broker-owned shared FileLog handles (no double-open/stale in-memory view), sealed-block push on every tick, pull-on-commit-recovery, epoch leases like user topics, and read-through `OffsetStore.Get`/`All` so cross-node commits are visible without refresh hooks. Queue-offset commits made on one node replicate to every node.

**Acceptance:** `TestInternalTopicReplicates` — produce/commit on the lease holder, block visible committed on all nodes, `Groups().FetchOffset` returns the committed value everywhere. `go vet ./... && go test ./... -count=1 -race` green, `golangci-lint` 0 issues.

**Review gate: mandatory (storage semantics on internal logs).**

## Phase F completion — single-writer fencing (delivered 2026-11-13, pending storage review)

Closes the known multi-writer fork hazard documented in `TestInternalTopicReplicates`; see the spec below (written before the code, as required). Result: internal-topic appends are fenced by the internal lease on a shared `fence.GateBox`; reads became HWM-gated read-through across all fold-cached internal stores; compaction is refused when fenced (renumbering would diverge replicas); the CLI retries seed nodes on fence errors; `TestInternalTopicSingleWriter` proves concurrent commits yield exactly one writer with byte-identical replicas.

**Acceptance:** `go vet`, `-race` suite green; `golangci-lint` 0 issues. Live 3-node smoke: non-holders 503 with an actionable fence error, holder serves the write, CLI retries seeds onto the holder, replicas converge byte-identical and serve reads everywhere.

**Review gate: mandatory (storage).**

Spec (written before the code, as required):

1. **Spike**: internal-topic writes are fenced by the topic's internal lease using a shared `fence.GateBox` (late-bound so cluster wiring can set it after the quorum starts; nil content = allow, single-node/in-memory unchanged). `Advisor.InternalGate()` allows a write only when this node holds a fresh lease for (name, 0) — the same Advisor used for user topics.
2. **Fenced stores**: `OffsetStore` (group commits), `AttemptStore` (queue attempt counters), `apikeys.Store` (key create/revoke), `audit.Store` (best-effort, refusals logged). All reads become **HWM-gated read-through** (cached fold reused while high watermark unchanged, full re-fold only when it moved) — the read-hot path stays O(1)-ish.
3. **Fail closed**: fenced writes return `fence.ErrFenced` (wrapped with topic + holder). gRPC maps it to `FailedPrecondition`; HTTP admin maps it to `503`. Queue `Pull` returns an error instead of undeliverable emptiness. CLI `create-apikey`/`revoke-apikey` retry across seed nodes. No silent divergence is possible.
4. **Compaction refused when fenced**: internal-topic Compact would renumber records → byte divergence in the replica set. Fenced stores reject explicit `Compact()` calls and skip auto-compact (`__consumer_offsets`/`__queue_attempts` grow with commit rate; documented like ADR-009). Single-node path unchanged.
5. **Test**: `TestInternalTopicSingleWriter` — concurrent `CommitOffset` on two nodes under a forced lease split: at most one node may succeed per call; after convergence all replicas byte-identical (blocks compared). Plus unit tests for the gate, and HWM-gated read tests. `TestCompactPreservesLastPerKey` must keep passing on the single-node path.
6. **Non-goals (documented)**: internal writes are *not forwarded* to the holder (client reroute: apps retry with fresh metadata; CLI retries seeds); no compaction of replicated internal topics; admin ops stay fail-closed rather than forwarded.
