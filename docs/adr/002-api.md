# ADR-002: API surface — clean API, not wire protocol

Status: accepted · 2026-11-13 · delivered (v0.1.0)

## Context

The two dominant broker families — streaming and queue — both encode decades of compatibility constraints in their wire protocols. Implementing either as the primary API couples us to someone else's design mistakes and turns "build a broker" into "implement someone else's behavior bug-for-bug".

## Decision

- **v1 API:** gRPC (internal/hot path: produce/fetch/ack) + HTTP/JSON for admin (create topic, list, metrics, health). Protobuf schemas in `internal/api`.
- **Wire compatibility with any other broker**: non-goal. If compatibility is ever needed, it ships as a separate **protocol gateway** process translating foreign requests ↔ internal API — never inside the broker core.
- **Any other broker's protocol**: same treatment, a separate decision later.
- Client SDKs (Go first) wrap gRPC so users never hand-roll requests.

## Consequences

- Fastest path to a correct, benchmarked core.
- No drop-in replacement for clients written against any existing broker in v1 — acceptable per ADR-001 scope.
- The gateway strategy keeps the door open without contaminating the design.
