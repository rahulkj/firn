# ADR-002: API surface — clean API, not wire protocol

Status: accepted · 2026-11-13 · delivered (v0.1.0)

## Context

Kafka's wire protocol and AMQP 0-9-1 both encode decades of compatibility constraints. Implementing either as the primary API couples us to other vendors' design mistakes and turns "build a broker" into "implement someone else's bug-for-bug spec".

## Decision

- **v1 API:** gRPC (internal/hot path: produce/fetch/ack) + HTTP/JSON for admin (create topic, list, metrics, health). Protobuf schemas in `internal/api`.
- **Kafka wire protocol**: non-goal. If compatibility is ever needed, it ships as a separate **protocol gateway** process translating Kafka requests ↔ internal API — never inside the broker core.
- **AMQP**: same treatment, separate decision later.
- Client SDKs (Go first) wrap gRPC so users never hand-roll requests.

## Consequences

- Fastest path to a correct, benchmarked core.
- No drop-in replacement for Kafka clients in v1 — acceptable per ADR-001 scope.
- The gateway strategy keeps the door open without contaminating the design.
