# ADR-005: MVP definition — what "working" means

Status: accepted · 2026-11-13 · delivered (v0.1.0) · amended 2026-11-13 (produce bar retired)

## MVP (v0.1.0) is done when all of these pass on a clean machine:

1. `slipwayd` starts, serves `/healthz`, creates a topic via HTTP admin API.
2. gRPC produce: 100k messages to a 3-partition topic without corruption.
3. gRPC fetch by offset returns messages in order, byte-identical payloads, across process restart (durable log).
4. Kill -9 during produce; on restart, no torn record is served and no acknowledged message is lost.
5. Consumer group `g1`: two members, partitions rebalanced, committed offsets resume after restart.
6. Queue mode: unacked message redelivered after visibility timeout; DLQ after 3 deliveries.
7. `go test ./...` incl. fault-injection recovery tests passes in CI.

## Explicitly not in MVP

Replication, exactly-once, wire protocols, auth, compaction, DLQ redrive tooling, metrics. Each is a later milestone with its own ADR.

## Benchmark bar (soft) — amended 2026-11-13

Original text (accepted with this ADR, never met as written): "Single-node, fsync-every-10ms: ≥ 50k msg/s produce, p99 fetch < 20ms for warm segments."

**Decision (2026-11-13): keep fsync-per-append; the 50k msg/s produce bar is retired.** The shipped `v0.1.0` semantics (`WithSyncOnAppend=true`, per ADR-004's acks=1) are one device flush per acknowledged produce — measured ~1.97 ms/op ≈ **508 msg/s** on the reference machine (Apple M3 Pro, `bench/baseline.md`). A 50k msg/s synchronous per-message produce rate is physically out of reach on commodity storage; it is only reachable with a bounded flush window (group commit: buffer N bytes or T µs, one fsync per batch, ack after the batch flush). That is a storage-semantics change and would therefore require: its own ADR, property tests for torn-tail and ack-after-flush invariants, and mandatory storage review before it ships. None of that is scheduled.

The bar for warm-segment fetch (**p99 fetch < 20 ms**, measured by `bench/`) is retained unchanged. Produce throughput expectation is ~500 msg/s per node until/unless a flush-window policy ADR is accepted — document this in release notes rather than claim 50k.
