# ADR-005: MVP definition — what "working" means

Status: accepted · 2026-11-13

## MVP (v0.1.0) is done when all of these pass on a clean machine:

1. `eventingd` starts, serves `/healthz`, creates a topic via HTTP admin API.
2. gRPC produce: 100k messages to a 3-partition topic without corruption.
3. gRPC fetch by offset returns messages in order, byte-identical payloads, across process restart (durable log).
4. Kill -9 during produce; on restart, no torn record is served and no acknowledged message is lost.
5. Consumer group `g1`: two members, partitions rebalanced, committed offsets resume after restart.
6. Queue mode: unacked message redelivered after visibility timeout; DLQ after 3 deliveries.
7. `go test ./...` incl. fault-injection recovery tests passes in CI.

## Explicitly not in MVP

Replication, exactly-once, wire protocols, auth, compaction, DLQ redrive tooling, metrics. Each is a later milestone with its own ADR.

## Benchmark bar (soft)

Single-node, fsync-every-10ms: ≥ 50k msg/s produce, p99 fetch < 20ms for warm segments. Measured by `bench/` and recorded in the release notes; not a hard release gate for v0.1.0.
