streams & queues, one log.

firn is an append-only, fsync′d event log with topics, partitions, replay and consumer groups on one side — and ack / redelivery / DLQ queue semantics on the other — in a single ~14 MB static binary. Secure by default: a fresh broker serves nothing until you mint its first key.

Why firn

One storage engine. Both semantics.

Most brokers force a choice: an event log or a task queue, maintained as two engines. firn keeps a single append-only, CRC-framed, fsync′d log per partition and layers streaming and queue semantics on top of it — one replication path, one audit trail, one set of backups.

Streaming

Topics, partitions & replay

FNV-1a key → partition assignment (round-robin when keyless), fetch by offset, per-partition ordering, whole-segment retention by TTL or bytes, consumer groups with range/round-robin assignment and restart-safe committed offsets.

Queue

Ack, redeliver, DLQ — broker-native

mode: "queue" topics: visibility leases, at-least-once redelivery, attempts counted per message, automatic diversion to <queue>.dlq after 3 attempts, firn-cli dlq redrive to re-inject.

Durable

fsync. CRC frames. Kill -9 tested.

Offsets are monotonic from 0 and never reused; fetch never returns records ≥ HWM; torn tails are truncated on open; the fault-injection suite SIGKILLs a child mid-produce and asserts no acknowledged record is lost.

Secure by default

Fail-closed, or not listening

Zero-key broker serves /healthz only; one-time bootstrap token mints exactly one admin key; SHA-256-hashed keys; roles (viewer/operator/admin); per-key + per-IP rate limits; mesh mTLS; append-only __audit in every mode.

Cluster

3-node HA, quorum-driven

Embedded Raft (no external coordination), content-addressed sealed blocks replicated over mTLS, epoch-fenced write leases, byte-identical replicas, client routing via GetMetadata. Single-region, fixed membership — GA within the documented envelope.

Federation

Byte-identical DR, preview

One-way passive replication preserves offsets exactly, fences the sink read-only, and ships with a cutover runbook. Active-active re-originates records with echo filtering. Cursors and replica lag are first-class metrics.

Honesty box
firn is not Kafka, and says so in writing. It sustains ~350–500 durable msg/s per node by default (fsync-per-append, measured; ~186 000 msg/s opt-in with the -flush-window group-commit path, ADR-014). No exactly-once, no transactions, no Connect/Streams ecosystem, no multi-tenant isolation, one maintainer, zero external production hours. If you need to run the business on it, use Kafka/Redpanda/Pulsar — or a managed service. If you want a broker you can read end-to-end and audit, keep reading.
