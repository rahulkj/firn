Installation

Every supported install path, with verification. Release binaries are static; the only runtime dependency is a filesystem that honors fsync.

From release tarballs (recommended)

# linux-amd64 shown; targets: darwin-arm64, darwin-amd64, linux-amd64, linux-arm64
gh release download v0.5.2 --repo rahulkj/firn \
  --pattern 'firn-v0.5.2-linux-amd64.tar.gz' --pattern 'SHA256SUMS'

# 1) integrity
shasum -a 256 -c SHA256SUMS
# 2) provenance — SLSA v1.0, built by .github/workflows/release.yml, Sigstore-logged
gh attestation verify firn-v0.5.2-linux-amd64.tar.gz --repo rahulkj/firn
# 3) (offline) gh attestation verify firn-v0.5.2-linux-amd64.tar.gz \
#      --bundle provenance.sigstore.jsonl --repo rahulkj/firn

tar -xzf firn-v0.5.2-linux-amd64.tar.gz   # firnd, firn-cli, README.md, LICENSE
sudo install -m 0755 firnd firn-cli /usr/local/bin/

Downloads live on the GitHub releases page; every release carries SHA256SUMS, an SPDX SBOM, and provenance.sigstore.jsonl. The full verification checklist is in docs/distribution.md.

As a service (systemd / launchd) — recommended for Linux & macOS

The interactive installer detects the OS, downloads the latest release tarball and verifies it against SHA256SUMS, creates a dedicated firn system user and a 0700 data directory, and prompts for everything the product needs — TLS paths, retention TTL, and for clusters: node-id, the peer list (including self), and the shared mesh CA (generate or use an existing bundle). It then installs and starts the unit, and prints the bootstrap-token → first-key → /healthz flow. Windows: use WSL2 or the OCI image.

sudo ./packaging/install.sh                      # interactive; safe defaults
sudo ./packaging/install.sh --version v0.5.2     # pin a release
sudo ./packaging/install.sh --unattended         # defaults, never -dev

Single node by default; choose cluster mode at the prompt (or pre-create the mesh CA and copy it to each node — see ADR-015 §3.2).

From source

git clone https://github.com/rahulkj/firn
cd firn
make build    # or: go build ./...
make verify   # go vet ./... && go test ./...
go build -o firnd ./cmd/firnd && go build -o firn-cli ./cmd/firn-cli

Requires Go 1.27+. No third-party runtime dependencies; the dependency set (grpc, prometheus client) is deliberately minimal and SBOM-scanned in release.

Single node (default)

Nothing is required beyond a writable -data-dir:

firnd -data-dir /var/lib/firn -http-addr :9460 -grpc-addr :9461
# bootstrap token on stderr (first boot only); POST /apikeys mints the admin key; done.
  • Dir must be 0700, files 0600 — -dir-mode-check (default on) refuses to start otherwise.
  • Backups: stop the broker, cp -a the data dir. Never patch segment files by hand.
  • Upgrades: stop → swap binary → start. The data format is not versioned; layout changes land in releases with migration notes.

Docker / Podman

docker run -d --name firnd -p 9460:9460 -p 9461:9461 -v firn-data:/var/lib/firn ghcr.io/rahulkj/firn:v0.5.2
docker logs firnd   # one-time BOOTSTRAP TOKEN; then POST /apikeys as in the Quickstart

deploy/compose/compose.yaml is a ready file for docker/podman compose (single node by default; --profile cluster runs a 3-node cluster with a shared mesh CA). deploy/compose/firnd.container is a rootless Podman Quadlet for systemd integration. Kubernetes

Two manifests cover both supported topologies, or use the Helm chart — all schema-validated and identical in shape:

# standalone
kubectl apply -f deploy/k8s/firn-standalone.yaml

# 3-node GA cluster — mesh CA Secret first:
openssl ecparam -genkey -name prime256v1 -out mesh-ca/ca.key
openssl req -x509 -new -nodes -key mesh-ca/ca.key -days 3650 -subj "/CN=firn-mesh-ca" -out mesh-ca/ca.crt
kubectl create namespace firn
kubectl -n firn create secret generic firn-mesh-ca --from-file=ca.crt=mesh-ca/ca.crt --from-file=ca.key=mesh-ca/ca.key
kubectl apply -f deploy/k8s/firn-cluster.yaml

# or Helm (fails loudly without the meshCA secret):
helm install firn ./deploy/helm/firn --set meshCA.existingSecret=firn-mesh-ca  # sdg:ignore credential-assignment

Fixed 3-node membership; node-id derived from pod hostname; PDB keeps two voters available; mesh CA copied into pods by an initContainer. See ADR-015.

TLS (recommended)

firnd -tls-cert /etc/firn/tls.crt -tls-key /etc/firn/tls.key
# both listeners share the cert — SANs must cover every host/IP clients dial
# min TLS 1.2; clients use -ca-cert on firn-cli or the system roots

Three-node cluster (v0.5.0+, GA within the envelope)

  1. Pre-provision the mesh CA once: firn-cli mesh-ca init -out ./mesh-ca (or reuse your PKI with -mesh-ca-bundle/-mesh-ca-key).
  2. Copy ca.crt + ca.key into each node's <data-dir>/mesh-ca/ (0600).
  3. Start three nodes with matching -node-id and the same -peers list including all three:
firnd -node-id n1 -peers n1=192.0.2.11:9471,n2=192.0.2.12:9471,n3=192.0.2.13:9471 \
  -http-addr :9460 -grpc-addr :9461 -data-dir /var/lib/firn
# n2, n3 identical modulo -node-id and -data-dir

Membership is fixed at startup; topics created in cluster mode fan out through the quorum (HTTP 202 propagating); produce/fetch route via GetMetadata to the partition's lease holder. Envelope: single-region, fixed membership, ≥3 voting nodes, full-restart upgrades, single-copy-of-metadata quorum. Rolling upgrades and dynamic membership are not supported (v1 limitation, documented in the ADRs).

Two-cluster federation (preview)

Passive one-way DR (byte-identical, offset-preserving, fenced sink) or active-active (re-originated records, echo-filtered). Registration is out-of-band with federation-scoped keys over the mesh listener. See the cutover runbook and Architecture → federation flows.

Dev mode

-dev (or -allow-open-bootstrap) disables auth entirely — no keys, no bootstrap token, loud warning. For local development only; never on a network interface you don't own.

Sizing notes (honest)

  • fsync bounds durable throughput per node (~350–500 msg/s measured, NVMe). -flush-window=2ms opts into group commit (see ADR-014 for the RPO trade-off you accept).
  • Internal topics (__consumer_offsets, __queue_attempts, __audit, __api_keys) replicate like user topics — capacity-plan disk and replication traffic accordingly.
  • Audit budget -audit-max-bytes (default 64 MiB per process) fails closed past the budget; rotation is operator-driven (see configuration).
