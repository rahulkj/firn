Release notes

Every version, what actually changed, and how to trust what you download. Full history: CHANGELOG.md · artifacts: GitHub Releases.

Verify any release (90 seconds)

# 1) download tarball + SHA256SUMS from the release page
gh release download v0.5.3 --repo rahulkj/firn --pattern 'firn-v0.5.3-linux-amd64.tar.gz' --pattern 'SHA256SUMS'
shasum -a 256 -c SHA256SUMS

# 2) provenance — built by release.yml from refs/tags/v0.5.3, Sigstore-signed, rekor-logged
gh attestation verify firn-v0.5.3-linux-amd64.tar.gz --repo rahulkj/firn

# 3) offline: gh attestation verify <tarball> --bundle provenance.sigstore.jsonl --repo rahulkj/firn
# 4) inspect the SBOM: sbom.spdx.json (golang + grpc + prometheus client + transitive deps)

Releases ship: per-target static binaries (darwin/linux × amd64/arm64), SHA256SUMS, SPDX SBOM, provenance.sigstore.jsonl. CI gates on every push to main: vet, tests, build, lint, grype critical CVEs. Cosign sign-blob remains a documented human step (distribution.md).

How a release is cut (workflow)

StepWhere
Push to main or PRci workflow: vet → tests (no -race) → build → golangci-lint v2.15.0; main adds the distribution job (SBOM + grype fail-on-critical)
Tag push (v*)release workflow: guard tag == version const → build 4 targets → package tarballs + SHA256SUMS → SBOM → SLSA attestation (actions/attest) → GitHub release with notes extracted from CHANGELOG
Manualcosign sign-blob (owner key), optional — never blocking

Release notes are cut verbatim from the matching ## vX.Y.Z section of CHANGELOG.md — missing section ⇒ the release workflow refuses to run. Idempotent: re-running re-uploads assets with --clobber.

v0.5.3 — 2026-11-14 current

No broker behavior change except one boot-breaking defect. The mesh CA loader only parsed the first PEM block, so an openssl-generated CA (openssl ecparam -genkey, whose file is EC PARAMETERS + EC PRIVATE KEY) failed to load and cluster nodes crash-looped at boot with a misleading no mesh CA found error. The parser now accepts any PEM bundle containing an EC key; the install docs recommend firn-cli mesh-ca init and pass -noout to openssl; regression test included. Also: k8s/Helm manifests use single-line command args (YAML line continuations mangled the flag list and every pod silently booted single-node) and chmod -R go-rwx on the data dir so NFS-provisioned 0777 PVCs pass firnd's startup mode check.

v0.5.2 — 2026-11-14

No broker behavior change — Go sources identical to v0.5.1 except the version const. Added the distribution story: multi-arch OCI image published on every tag push (ghcr.io/rahulkj/firn:v0.5.2 + :latest, linux/amd64+arm64, uid 10001, healthz HEALTHCHECK), the interactive packaging/install.sh (systemd/launchd, SHA256SUMS-verified install, cluster prompts: node-id, peers, mesh CA), plain Kubernetes manifests (standalone + GA 3-node cluster), a Helm chart, OCI Compose files, and a rootless Podman Quadlet. See ADR-015.

v0.5.1 — 2026-11-14

No broker behavior change — Go sources identical to v0.5.0 except the version const. Exists so the release pipeline ships inside the tagged tree: the release workflow triggers on push: tags and provenance records refs/tags/v0.5.1 exactly (v0.5.0's attestation, cut via dispatch, records refs/heads/main). SLSA v1.0 provenance now attestation-gated on every future tag.

v0.5.0 — 2026-11-14

  • Cluster mode GA (envelope: single-region, fixed membership, ≥3 voters, full-restart upgrades): 2-node validated end-to-end; two live-found defects fixed — replication agent dialed the client gRPC port instead of mesh mTLS (no block ever replicated in v0.4.0), and DLQ divert silently dropped poison messages on multi-node clusters (now quorum-created on every node + routed via mesh-only RoutedBrokerService; divert failure fails the claim).
  • ProduceBatch / AckBatch RPCs (one RPC per batch); AckBatch drain ~2075 deliveries/s vs ~196 per-message.
  • ADR-014 group commit / flush window behind -flush-window (default 0): ~186k msg/s durable produce with 256 in-flight producers. Kill −9 storm test added.
  • ADR-007 cluster metric surface: firn_blocks_sealed_total, firn_block_bytes_sealed_total, firn_blocks_pushed_total, firn_blocks_committed_total, firn_lease_grants_total, firn_lease_renewals_total — verified live.
  • Mesh FederationService now also requires a federation-scoped key (mTLS alone used to suffice). CIDR allowlist enforced on the bearer path (was cookie-path only); -anon-rate 0 now correctly means unlimited; /healthz reports -flush-window.
  • Browser session auth for /ui/ (ADR-013 Slice C); docs/operator.md, docs/sre.md full metric catalog; comparison doc.

v0.4.0 — 2026-11-13 breaking

  • Secure by default: zero keys ⇒ /healthz only; one-time bootstrap token; metrics viewer-gated; anonymous CIDR limits; audit always-on; data-dir perms enforced; HTTP hardening headers; SBOM+grype+cosign release hardening.
  • Listener defaults moved to IANA-unassigned ports: :9092/9093 → :9460/:9461 (mesh :9471) — see migration guide.
  • ADR-010 federation preview: passive one-way DR (byte-identical, offset-preserving, fenced cutover) + active-active with echo filtering; federation keys; FetchResponse.federation_hwm; firn_federation_cursor_lag_seconds; /ui/federation.
  • ADR-012 architecture map published; SDK sdk/firngo shipped.

v0.3.0 — 2026-11-13 breaking

Rename to Firn (module path, binaries, proto package firn.v1, metrics prefix, env vars). MIT LICENSE added. Quorum liveness fix (per-election re-randomized timeout).

v0.2.0 — 2026-11-13

ADR-007 scaled deployment preview (behind flags): block engine (content-addressed sealed blocks), embedded Raft metadata quorum, lease-fenced single-writer partitions with TTL, block replication + unsealed-tail re-replication, client routing via GetMetadata.

v0.1.0 — 2026-11-13

First MVP: topics/partitions/replay, fsync'd segment FileLog with CRC frames + torn-tail recovery, kill −9 test, whole-segment retention, consumer groups over __consumer_offsets, queue mode with visibility leases and DLQ, /metrics + structured logs, firn-cli.
