Six-minute orientation

1. A topic is an append-only log split into partitions; each record gets a
   monotonically increasing offset. Fetch is by (topic, partition, offset).
2. Pick a mode at creation: "stream" (replay freely, consume with groups)
   or "queue" (pull + ack, redelivery, DLQ). Same storage engine both ways.
3. Auth is fail-closed: no keys ⇒ /healthz only. The first boot prints a
   one-time BOOTSTRAP TOKEN; POST /apikeys with it mints the first (admin) key.
4. fsync per append by default. -flush-window=2ms opts into group commit
   (documented RPO trade-off, ADR-014).
5. Single node by default. 3-node with -node-id/-peers for HA (quorum, leases).
6. Audit (__audit) records every admin mutation and authz refusal, always.
